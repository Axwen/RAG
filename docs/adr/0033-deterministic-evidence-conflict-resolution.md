# 跨知识空间证据冲突按全序键确定性消解，不交由模型自由裁决

原设计给出了冲突处理的原则性排序（权威级别优先、范围匹配优先、新鲜度优先），但没有给出可实现的全序算法，也没有规定 `CONFLICT` 引用状态的触发条件。原则不构成确定性：两个知识空间的证据合并顺序不同就可能产生不同回答，这直接违反"同一输入可复现"这条评测前提。

排序键定义为一个全序，依次比较：知识权威级别（`OFFICIAL` > `STANDARD_SCRIPT` > `TICKET_DERIVED`，级别是知识空间与文档版本上的显式字段，不从内容推断）；适用范围匹配度（产品、版本、地区、渠道等维度上精确匹配的数量，多者优先，通配匹配不计分）；有效期新鲜度（`valid_from` 较新者优先）；文档版本创建时间较新者优先；最后以 `documentVersionId` 字典序兜底。最后一项保证全序，不允许出现"并列"从而依赖合并顺序。跨空间 fan-out 的证据在合并后统一按此键排序，排序结果不得依赖空间的遍历顺序。

`valid_to` 已过期的证据不进入生成上下文，只能作为"该条知识可能已失效"的提示条目展示，引用状态为 `EXPIRED`。

`CONFLICT` 的触发条件是：同一回答句所绑定的证据中，存在两条在排序键前两项（权威级别与范围匹配度）上完全相同、却对同一事实给出不相容结论的候选。此时不允许按后续键静默择一，引用状态置为 `CONFLICT`，界面必须同时展示两条来源并标注冲突，回答不得给出单一确定结论。模型不承担裁决职责，裁决只发生在上述显式字段上。

`CONFLICT` 是 `AnswerFinalizer` 的硬门禁：包含未解决冲突事实句的运行不得提交为 `ANSWERED`，只能提交为 `PARTIAL`、`EVIDENCE_ONLY` 或 `REFUSED`。Finalizer 的选择、冲突来源和最终状态必须写入 `RetrievalSnapshot`、AnswerRun 事件和领域审计。

DoD 要求黄金集包含权威冲突题、范围重叠题和过期知识题，并要求同一输入在固定 `RetrievalSnapshot` 上重复运行得到相同的候选顺序与相同的引用状态。冲突判定与消解结果写入 `RetrievalSnapshot`，使事后能区分"检索没找到"与"找到了但被判为冲突"。
