# 引用验证分层预算：常规走 token 与向量，蕴含校验只用于高风险

> 本 ADR 于 2026-08-26 按 PROBE-005 实测**原地修订**：常规路径 P95 ≤ 600 ms 与高风险路径 P95 ≤ 1.5 s 两个目标在实测供应商上均不可达，按实测重新冻结。分层结构、验证内容、缓冲与费用口径不变。修订记录见文末。

原预算把引用验证整体压在 P95 ≤ 200 ms，同时要求验证包含 token、向量和蕴含三项。逐句向量回填需要云 Embedding 调用，蕴含校验需要额外一次 LLM 调用，两者都是网络往返，200 ms 不可能成立。本 ADR 按风险分层重新定义验证内容和预算。

## 常规路径：P95 ≤ 2.0 s

常规问题的引用验证由句切分、token 重叠和向量相似度回填组成。逐句 Embedding 必须合并为一次批量调用，不允许每句一次请求。**该路径预算为 P95 ≤ 2.0 s。**

实测依据（PROBE-005 Stage A，OpenRouter `qwen/qwen3-embedding-8b`）：批量 1/4/8 条的单次调用延迟为 1.04 / 1.41 / 1.37 s。**云 Embedding 的一次往返已占 1.4 s 量级，原 600 ms 目标在任何云 Embedding 供应商上都不可能成立**，与其把不可达数值写进 DoD，不如按实测冻结并把余量留给句切分与本地 token 重叠计算。

验证结果落在 `VERIFIED`、`WEAK` 或 `PENDING`，`WEAK` 必须在界面显式标注为证据支持不足，不得静默当作已验证。

## 高风险路径：P95 ≤ 3.5 s，且蕴含调用必须与逐句 Embedding 并发

高风险问题在 token 与向量之外增加一次 LLM 蕴含校验，逐句判定"该事实句是否可由绑定证据推出"，**预算为 P95 ≤ 3.5 s**。

实测依据（PROBE-005 Stage B，fluxionai `gpt-5.6-terra` · Responses API，两次独立运行）：流式 TTFT 1.82-2.22 s，一次完整生成 2.9-3.0 s，非流式单次 2.8-3.3 s。**原 1.5 s 目标连一次蕴含调用都装不下。**

**并发约束（新增，实现必须遵守）**：3.5 s 的前提是**逐句 Embedding 批量调用与蕴含校验调用并发发起**——两者的输入都只依赖「答案事实句 + 已绑定证据」，不存在先后依赖。若串行执行，实测下界约为 1.4 s + 3.0 s ≈ 4.3-4.4 s，必然超预算。因此该并发要求属于本 ADR 的硬约束，不是优化建议。

该路径继续保持生成前缓冲：缓冲上限 2,048 output tokens，验证通过前不向客户端发送任何事实正文；验证失败或超时返回 `EVIDENCE_ONLY` 或 `REFUSED` 并释放缓冲。`AnswerFinalizer` 只提交经过允许验证状态的最终快照这一约束不变。

## 费用口径（不变）

费用口径必须显式包含验证成本。单次问答预算 ≤ 5 元的计算范围为：查询改写与 Chat 生成、查询向量、逐句验证向量，以及高风险路径的蕴含校验调用。预扣按该口径一次性完成，不允许把验证调用当成"预算外的附加调用"。蕴含校验的结构化输出只走 strict `json_schema`（见 [ADR-0017](0017-mvp-cloud-model-and-budget.md) 第 3 节），Responses 方言的 `reasoning_tokens` 计入 output 侧成本。

## 门禁与阶段 2 出路（不变，含实测补充）

引用正确率不进入阶段 1 的阻断门禁，但必须在固定黄金集上按上述两条路径分别报告，并与引用覆盖率一起观察，避免用弱相关证据把覆盖率刷上去。

蕴含校验替换为本地小模型是阶段 2 的可选优化：那会改变"阶段 1 只使用云模型执行区"的边界，需要另立 ADR，不在本决策内。**实测补充**：常规路径若要回到亚秒级，同样只有「验证用 Embedding 本地化或缓存」这一条路（云往返 1.4 s 是硬下界），与上述阶段 2 优化属同一决策，一并另立 ADR。

## 修订记录

- **2026-08-26（PROBE-005）**：常规路径 600 ms → **2.0 s**（依据 Stage A 批量 Embedding 1.04-1.41 s）；高风险路径 1.5 s → **3.5 s**（依据 Stage B TTFT 1.82-2.22 s、完整生成 2.9-3.0 s），并新增「逐句 Embedding 与蕴含调用必须并发」硬约束（串行下界 ≈ 4.3 s）。两个数值绑定当前供应商基线（OpenRouter Embedding + fluxionai Chat），换供应商须按 PROBE-005 探针复测后重新冻结。实测明细见 `docs/engineering/probe-results/probe-005-model-adapter*.md`。
