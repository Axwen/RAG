# 引用验证分层预算：常规走 token 与向量，蕴含校验只用于高风险

原预算把引用验证整体压在 P95 ≤ 200 ms，同时要求验证包含 token、向量和蕴含三项。逐句向量回填需要云 Embedding 调用，蕴含校验需要额外一次 LLM 调用，两者都是网络往返，200 ms 不可能成立。本 ADR 按风险分层重新定义验证内容和预算。

常规问题的引用验证由句切分、token 重叠和向量相似度回填组成。逐句 Embedding 必须合并为一次批量调用，不允许每句一次请求。该路径预算为 P95 ≤ 600 ms。验证结果落在 `VERIFIED`、`WEAK` 或 `PENDING`，`WEAK` 必须在界面显式标注为证据支持不足，不得静默当作已验证。

高风险问题在 token 与向量之外增加一次 LLM 蕴含校验，逐句判定"该事实句是否可由绑定证据推出"，预算为 P95 ≤ 1.5 s。该路径继续保持生成前缓冲：缓冲上限 2,048 output tokens，验证通过前不向客户端发送任何事实正文；验证失败或超时返回 `EVIDENCE_ONLY` 或 `REFUSED` 并释放缓冲。`AnswerFinalizer` 只提交经过允许验证状态的最终快照这一约束不变。

费用口径必须显式包含验证成本。单次问答预算 ≤ 5 元的计算范围为：查询改写与 Chat 生成、查询向量、逐句验证向量，以及高风险路径的蕴含校验调用。预扣按该口径一次性完成，不允许把验证调用当成"预算外的附加调用"。

引用正确率不进入阶段 1 的阻断门禁，但必须在固定黄金集上按上述两条路径分别报告，并与引用覆盖率一起观察，避免用弱相关证据把覆盖率刷上去。蕴含校验替换为本地小模型是阶段 2 的可选优化：那会改变"阶段 1 只使用云模型执行区"的边界，需要另立 ADR，不在本决策内。
