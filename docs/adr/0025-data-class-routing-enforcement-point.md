# 数据分级路由的强制执行点在 ModelAdapter，而不是独立模型网关

ADR-0005 确定了正确的约束：普通资料可以调用批准的云模型，敏感资料及其查询、证据和衍生内容只能进入企业网络内的本地模型执行区；路由由服务端强制执行，不由用户、前端或 Prompt 选择；本地模型不可用时敏感请求必须明确失败或只返回受控检索结果，不得降级到云模型。该约束继续有效。

ADR-0005 把执行者写成"服务端模型网关"，与阶段 1 不部署独立 Model Gateway 的边界不一致。本 ADR 明确：阶段 1 的强制执行点是 NestJS 内部 `ModelAdapter` 的准入层，它是所有 Chat、Embedding、Reranker 和引用验证调用的唯一出口。业务模块不得绕过 `ModelAdapter` 直接构造 HTTP 请求或引入第二个模型客户端。

准入层在每次调用前必须收到显式的 `dataClass` 与 `executionZone` 参数，不允许默认值和推断。`dataClass` 为 `UNKNOWN` 或属于敏感等级时，云执行区调用一律拒绝并返回可解释的阻断原因，不进入任何降级链；降级链只能在同一执行区内部由高质量模型降到低成本模型，再降到仅检索结果或明确不可用。阻断和降级都写领域审计。

`ModelAdapter` 同时是模型预算预扣的唯一入口（见 ADR-0029）。把数据分级准入和预算预扣放在同一处，是为了保证"任何模型调用都同时经过分级和预算两道闸门"这一性质可以用单点契约测试证明，而不需要审计整个代码库的调用点。引用验证使用同一 `ModelCallContext`，不能通过另一个 LLM 客户端绕过该准入层。

未来出现多个独立应用、跨租户统一路由、独立扩缩容或统一网关治理需求时，可以把该准入层原样搬到独立进程。届时新增 ADR 记录进程边界变化，本 ADR 描述的约束和参数契约不变。
