# 阶段人工核验门禁

> 生效日期：2026-08-28  
> 状态：阶段 1 实施硬门禁。自动化检查、代码评审或 Agent 自评均不能替代用户人工验收。

## 结论

每个实施批次结束后必须暂停推进，由主 Agent 汇总可运行成果、UI/API 表面、关键代码、验证证据和已知缺口，交给用户人工核验。只有用户明确给出验收结论并允许继续后，才能启动下一实施批次。

## 并行 Agent 规则

- 本规则生效时已经运行的 Agent，可以完成其**原始分配范围**，但不得自行扩展范围或领取下一批次任务。
- 当前并行 Agent 全部结束后，由主 Agent 统一整合结果、处理冲突并准备一份验收材料；不得把多个 Agent 的“完成”声明直接视为阶段完成。
- 进入 `READY_FOR_HUMAN` 后，默认停止对本批次相关文件的继续写入。只有用户要求修正验收问题时才重新进入实现。
- 人工验收通过只表示允许进入下一实施批次，不等于授权 `commit`、`push`、PR、merge 或部署；这些 Git/发布操作仍需单独明确授权。

## 验收材料

每次人工核验必须一次性提供以下内容，避免用户只能相信黑盒结论：

1. **范围与结果**
   - 本批次原定目标；
   - 已完成、部分完成、未完成和明确不在范围内的内容；
   - 从用户视角可以做什么，不能做什么。
2. **UI 与可操作表面**
   - 改动 UI 时：提供访问地址、关键页面截图、主路径操作步骤，以及加载、空状态、错误状态等受影响状态；
   - 仅后端批次：明确写“本批次无新增产品 UI”，提供可执行的 API/CLI/数据库效果演示，并说明现有 UI 是否变化、产品 UI 将在哪个后续批次出现；
   - 不得用静态测试结果代替真实页面或接口演示。
3. **代码导览**
   - 修改文件清单和职责；
   - 关键入口、主要调用链和数据流；
   - 重要设计决策，以及没有采用更复杂方案的原因；
   - `git diff --stat` 和无关修改检查结果。
4. **验证证据**
   - 实际执行的测试、类型检查、Lint、构建、浏览器 QA 或集成命令及结果；
   - 未执行的验证及原因；
   - 自动化验证只能证明进入人工核验的条件已满足，不能代替人工结论。
5. **风险与遗留**
   - 已知缺陷、临时限制、兼容性风险、数据或权限风险；
   - 需要后续批次处理的事项及其归属；
   - 任何会改变下一批次产品行为的待决策项。

## 状态与流转

```text
IMPLEMENTING -> READY_FOR_HUMAN
READY_FOR_HUMAN -> ACCEPTED | ACCEPTED_WITH_ACTIONS | REJECTED
REJECTED -> IMPLEMENTING -> READY_FOR_HUMAN
```

约束：

- `READY_FOR_HUMAN` 只能由主 Agent 在整合全部并行结果后声明。
- 没有用户明确结论时，状态保持 `READY_FOR_HUMAN`，不得默认超时通过。
- “有条件通过”必须由用户明确说明可以继续；Agent 不得自行判断遗留项不重要。
- 验收结论写入对应验收记录，并同步 `PROJECT_STATE.md` 的当前状态和下一步。

若某一批次过大、用户要求提前查看，或出现公开 API、数据结构、安全边界、UI 方向等关键决策，必须增加临时人工门禁，不必等到表中的固定门禁点。已决定设置的临时门禁一律登记进上表并带 `（临时）` 标记：只写在 `PROJECT_STATE.md` 里的门禁，下一个人读门禁表时看不到，等于没有。

HG-01a 的设置理由：身份接入是后续所有受保护路由的地基。T14a 的 7 张业务身份表在 HG-01 内还没有业务数据，此时改结构只是改迁移；等 T14b 的授权判定和受保护 Web 路由都压在上面之后再改，代价完全不同。在开工 T14b 之前让用户看一遍真实登录链路与表结构，比在 HG-01 一次性验收整批更早暴露方向性问题。

## 验收记录模板

每次验收在 `docs/engineering/acceptance/` 下建立独立记录：

```markdown
# HG-XX：<批次名称> 人工验收

- 状态：READY_FOR_HUMAN | ACCEPTED | ACCEPTED_WITH_ACTIONS | REJECTED
- 提交验收日期：YYYY-MM-DD
- 用户结论日期：待定

## 1. 范围与结果
## 2. UI / API / CLI 操作说明
## 3. 代码导览
## 4. 自动化与真实环境验证
## 5. 已知风险与遗留
## 6. 用户验收结论
```

验收记录不得预填“用户已通过”。在用户明确回复前，结论必须保持“待定”。
