README 对每步都有对应说明,验收口径"从干净检出可以用仓库文档中的命令完成冻结安装"成立。

### DX 遗留摩擦(记录,不在 T0 修)

1. **应用进程不自动加载根 `.env`**(最主要摩擦)。Compose 自动读,但 `pnpm --filter @rag/api dev` 等应用脚本需要手工 `source .env` 或 direnv。README 已如实说明,但每个开发者每次启动都会碰到。候选方案(留给后续票据顺路处理):dev 入口统一预载根 `.env`(dotenv,不覆盖已存在变量),或团队约定 direnv。不在 T0 追加,避免为了顺手改启动语义。
2. **CI 尚未真实运行过**。仓库无远程,`push`/`pull_request` 触发器无法验证;action 版本(checkout v7 等)为定稿时的 latest,未经真实运行检验。建远程后第一次 CI 运行即是要点,T1a 提交前应关注。
3. `tsconfig.test.json` 携带 `experimentalDecorators`/`emitDecoratorMetadata`(NestJS DI 需要),理由已写在 eslint 配置注释与评审报告;新人首个 PR 可能在此疑惑,文档已可解答。

## 二、实现准备增量工程复审

### 真实工具链确认(全部为已实测运行,非纸面)

Node 22.23.1 / pnpm 10.34.5 / TypeScript 5.9.3(strict)/ ESLint 10(flat config)/ Vitest 4 / NestJS 12 / Next 16.3.3 / Prisma 7.10.0(prisma-client 生成器,CJS 产物)/ Python 3.12.3 + uv 0.12.5 / FastAPI 0.141。

### 依赖图确认(pnpm workspace 实测)

```text
contracts(叶,零依赖)
config → zod
observability → pino
rag-core → contracts
database → @prisma/client、pg、observability
api → contracts/config/database/observability/rag-core + NestJS
worker → 同上四包(复合入口)
web → 独立 Next.js(不依赖任何共享包,T0 正确)
parser → 独立 uv 项目
```

无循环、无越层。分层与 ADR-0010/0024 一致:契约在最底,数据库经 observability 出日志,应用只复合。

### 批次与周期结论

- **T0 估算校验**:估算 human ~4d / CC ~1d;实际 CC 约 1 人日(2026-08-27 合并后开工,08-28 完成并过全验收,含一次交接)。**估算口径可信,不调整换算系数。**
- **批次冻结**:第一批 T1a + T14 + T11(同步审计)+ T12(Ledger 骨架)**维持不变**。T1a 的落点(`packages/database/prisma/schema.prisma`、`packages/contracts`)在 T0 中已按 Prisma 7 边界备好;T14 的 Realm 四角色已在初始化脚本中导入;T11 的审计表与 T2 状态事务的依赖顺序不受 T0 实现细节影响。
- **十八张票合计维持 human ~84.5d / CC ~20.6d、整窗 24–36 周口径**;重估仍按原计划放在 Probe Gate 全闭合之后。

### 风险与后续票据的连带项(新增/确认)

1. **T3/T5/T6 的 Testcontainers 集成测试需要 CI 提供 Docker**。当前 CI 只做静态检查 + parser 镜像构建(有意为之,T0 不做集成);T3 开工时给 CI 增加 docker 可用的集成 job,随票交付。
2. **T1a 将交付 T0 显式留空的两项**:首个领域迁移 SQL 与最小领域种子(开发种子 `rerankInputSize=64` 显式写入,不读环境变量)。T0 的空种子路径已验证可成功,交接无障碍。
3. Keycloak 健康探针用容器内 `/dev/tcp` + 宽松正则(镜像无 curl),MinIO 用镜像自带 curl;两者已实测 healthy。若未来升级镜像标签,健康检查是首要回归点。
4. 应用 `.env` 注入摩擦(上述 DX-1)建议在 T14(Web 登录联调)或 T1a dev 种子联调时顺路解决,届时自然要写启动文档。
